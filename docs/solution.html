Chrome “Are you sure you want to allow this site to access your files?” prompt

Short answer

No — you cannot reliably bypass or suppress this security confirmation dialog in Chrome when using window.showDirectoryPicker().

It is a deliberate one-time user consent dialog for top-level FileSystemDirectoryHandle access.

Why the dialog appears (and why it stays)

  • The File System Access API is powerful: it allows persistent read/write access to a whole directory (even after page reload / browser restart if you store the handle).
  • Chrome (and most other browsers) require explicit user confirmation the first time a site calls showDirectoryPicker().
  • This is a top-level permission gate — similar in spirit to camera/microphone/location permissions.
  • Even if you already have permission to a subdirectory, calling showDirectoryPicker() again usually triggers the dialog again.

Bottom line: the dialog is intentional security UX. There is no standard flag, origin trial, or permission policy that removes it as of March 2026.

What you can do to improve the experience

  1. Call showDirectoryPicker() only once and persist the handle using IndexedDB or localStorage + handle.requestPermission()
  2. Show nice instructions before you trigger the picker
  3. After getting the directory handle, verify / request permission again only when needed (usually does not show the scary dialog if already granted)

Recommended pattern 2025–2026

// 1. Try to restore previously used folder
async function getPersistedDirectoryHandle() {
  const db = await openDB(); // your IndexedDB wrapper
  const savedHandle = await db.get('directoryHandles', 'user-folder');
  if (!savedHandle) return null;

  // Very important: check & possibly re-grant permission
  if ((await savedHandle.queryPermission({mode: 'read'})) === 'granted' ||
      (await savedHandle.requestPermission({mode: 'read'})) === 'granted') {
    return savedHandle;
  }
  return null;
}

// 2. Main slideshow start logic
async function startSlideshow() {
  let dirHandle = await getPersistedDirectoryHandle();

  if (!dirHandle) {
    // This is the call that shows the big confirmation dialog (first time)
    try {
      dirHandle = await window.showDirectoryPicker({
        mode: 'read',                 // or 'readwrite' if you need to write
        startIn: 'pictures',          // optional hint
        multiple: false
      });

      // Save for next time
      const db = await openDB();
      await db.put('directoryHandles', dirHandle, 'user-folder');
    } catch (err) {
      if (err.name === 'AbortError') {
        alert("Folder selection cancelled.");
      }
      return;
    }
  }

  // Now you can use dirHandle without showing dialog again (most cases)
  showSlideshow(dirHandle);
}

Key point: After the user has granted permission once and you stored the handle, most subsequent calls to requestPermission() will not trigger the big “Are you sure?” dialog — only a small permission sheet (if anything).

Alternatives that avoid the dialog completely

Method Shows big dialog? Persistent access? Notes
input type="file" webkitdirectory No No One-time selection, cannot save handle, user must pick again every visit
Drag & drop folder No No Same limitation as above
showDirectoryPicker() Yes (first time) Yes (if you store handle) Best UX long-term — this is what you should use

Summary — What should you do?

Use showDirectoryPicker() + persist the handle in IndexedDB
→ The scary dialog appears **only once** (or very rarely).
→ After that your slideshow can start instantly on future visits.

That is still — by far — the best user experience possible in 2026 for a local-folder-based slideshow in the browser.
